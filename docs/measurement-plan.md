# BaliXperience measurement plan

## Purpose

Measure whether visitors can find a suitable package and send a genuine booking request without creating an advertising-profile system.

## Primary outcome

- Booking requests submitted.

## Leading indicators

- Tour searches.
- Collection selections.
- Tour views.
- Dates selected.
- Checkout starts.
- WhatsApp clicks.

## Interpretation

The admin analytics screen reports event counts, not unique visitors. A person can create more than one event. Use the funnel to find large drop-offs and compare tour interest; do not treat it as exact attribution or revenue reporting.

## Privacy boundary

Conversion events contain only the event name, page path, optional tour/collection/destination context, traveler count, quoted IDR value, and timestamp. They must never contain names, email addresses, phone numbers, message text, IP addresses, cookie identifiers, or browser fingerprints.

## Weekly review

1. Compare tour views, checkout starts, and booking requests.
2. Review the tours with the most checkout starts but no requests.
3. Check WhatsApp clicks alongside submitted requests.
4. Review cancellation rate and estimated margins separately in the bookings and margins screens.
5. Change one meaningful page element at a time and allow enough traffic before drawing a conclusion.
